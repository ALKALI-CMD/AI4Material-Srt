# 项目详细笔记：通用机器学习力场的原子级归因分析

## 1. 当前项目定位

本项目第一阶段不重新训练大模型，而是围绕已有预训练机器学习力场做可解释性分析。当前采用的工作定义是：

> 在给定模型、给定结构路径和给定输出目标下，分析哪些原子或局域结构对模型输出变化贡献更大。

这里的“贡献”首先是模型归因，不直接等同于真实物理键能或唯一的原子能量分解。这个边界很重要，因为 MACE、CHGNet 等模型内部的消息、张量范数、原子能量头都可能有解释价值，但不能未经验证就被称为真实相互作用能。

## 2. 第一阶段为什么先做力场

优先选择 MACE/MACE-MP 和 CHGNet，而不是同时展开力场和哈密顿模型，原因是：

- 两者都有公开仓库、预训练模型和 ASE 接口；
- 可以先在能量、力、结构扰动上建立统一归因协议；
- 钙钛矿结构畸变、Pb-I 八面体扰动、缺陷附近局域环境都可以由力场模型快速验证；
- 哈密顿模型如 DeepH-E3、HamGNN 更适合作为第二阶段扩展，用于电子结构和轨道块解释。

## 3. 当前已落地的最小可运行切片

当前代码已经实现：

- `atomlens.structures`：生成 `diamond_si`、`cubic_cspbi3` 和固定组成的 CsPbI3 碘位移结构对；
- `atomlens.attribution`：基于力积分的坐标路径归因；
- `atomlens.models`：预留 MACE-MP 与 CHGNet 的 ASE calculator 适配器；
- `atomlens.cli`：提供 `atomlens smoke` 命令；
- `tests/`：验证归因 completeness、原子顺序检查、平移不变性和旋转不变性；
- `results/phase1_smoke_harmonic.json`：第一份可复现实验输出。

## 4. 第一阶段归因方法

对固定原子数、固定元素顺序、固定晶胞的结构路径：

```text
R(alpha) = R0 + alpha * (R1 - R0)
```

定义第 `i` 个原子的归因：

```text
A_i = - dR_i dot integral_0^1 F_i(R(alpha)) d alpha
```

其总和应近似：

```text
sum_i A_i = E(R1) - E(R0)
```

这个性质可以作为数值自检。如果残差很大，说明路径积分步数不够、模型力不稳定、结构路径不合理，或者 calculator 输出存在单位/接口问题。

## 5. 近期实验顺序

1. 本地用解析 harmonic calculator 验证公式与代码。
2. 在 GPU 服务器上安装 MACE/CHGNet 环境。
3. 用 `diamond_si` 做模型加载 smoke test。
4. 用 `cubic_cspbi3` 和碘位移结构对计算能量差归因。
5. 检查平移、旋转、原子重排、积分步数收敛。
6. 只在这些检查通过后，再讨论 Pb-I 键、八面体畸变、缺陷邻域等物理解释。

## 6. 火山服务器运行约束

用户已指定使用已有火山 GPU 服务器，并要求：

- 每个训练或实验进程最多使用 2 张 GPU；
- 独立实验可以并行；
- 初始预训练推理和归因默认 1 张 GPU，只有批量结构或高通量积分时再考虑 2 张 GPU。

远端第一个目标不是训练，而是复现实验环境：

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
atomlens smoke --calculator harmonic --steps 65
```

随后再安装模型依赖：

```bash
python -m pip install ".[models,viz]"
```

## 7. 后续扩展

MACE 主线可以进一步分析：

- 不同积分步数下的归因收敛；
- CsPbI3 八面体畸变路径；
- 同组成不同畸变幅度下的关键原子排序；
- tensor product 通道范数和路径归因之间的一致性。

CHGNet 主线可以进一步分析：

- 与 MACE 在相同结构路径上的归因模式是否一致；
- 结构能量差、力方向和局域配位畸变之间的关系；
- 模型对钙钛矿 A 位、B 位和卤素位扰动的敏感性。

哈密顿扩展暂时放在第二阶段：

- DeepH-E3 用作 E(3) 等变哈密顿预测文献基线；
- HamGNN 用作更现代的代码扩展候选；
- 重点转向哈密顿矩阵块、轨道相互作用和带隙相关归因。
